# 🔴 P0 — 仍需优先处理

## 1️⃣ Hover 浮层依然是"内联插入"，列表被挤走（上轮未修）

看截图 2：hover 第 4 行后，第 5–9 行（`change(isp)` 到 `feat(sensor): add rs0551c_mipi`）**整段消失**，只剩最后两行被挤到底部。

- ❌ 这是典型 **layout shift**：鼠标只要微移就可能触发列表重排 → 误拖、误点风险极高
- ❌ 用户失去上下文：正想比较相邻 commit，结果相邻 commit 被顶掉了

修复方式（二选一）：

```
✅ 方案 A：position: fixed 浮层
   - 覆盖在列表之上，不参与文档流
   - 1px border + var(--vscode-widget-shadow)
   - 靠近视口边缘时自动上/下翻转
   - 与触发行之间保留 4px gap + 200ms 关闭宽容期

✅ 方案 B：改为独立「详情」区（底部固定分栏）
   - 面板底部常驻 ~140px 详情区，随选中行更新
   - 优点：无浮层闪烁、可放更多操作按钮
   - 缺点：常占高度，需可折叠
```

> 建议 A，成本最低且不改变现有交互模型。

## 2️⃣ 圆点从"彩色"变成了"全灰"——信息量归零

截图 5 中三位作者（`lawrence_lv` / `sally_peng` / `yucheng_xiang`）的圆点**颜色完全一致**。

- ❌ 上轮建议是"把 hash 随机色改为作者语义色"，现在变成了"取消颜色"，等于**去掉了一个视觉通道却没补上语义**
- ❌ 而"识别他人 commit"恰恰是本插件锁定功能的核心场景，最需要一眼可辨

建议：

| 元素 | 做法 |
|---|---|
| 圆点填色 | 按 **author email 哈希** 取色，HSL 固定 `S/L`，随主题调 `L` |
| 圆点内容 | 作者首字母（`L` / `S` / `Y`），色觉障碍用户也能区分 |
| 「非我」标记 | 非当前 `user.email` 的 commit，圆点加 1px 描边或右侧加 `👤` |
| 图例 | 面板 `...` 菜单放「颜色图例」，避免猜 |

## 3️⃣ 撤销（Undo）依然缺失

工具栏仍是 4 个图标（Push / Stash / Pop / Refresh），**没有撤销入口**。

- rebase 全流程都在改写历史，而 UI 完全没有"回到操作前"的出口
- 用户唯一退路是自己去终端敲 `git reset --hard ORIG_HEAD`，这与"可视化封装"的产品定位矛盾

最小实现：

```
1. 每次改写历史前打 ref：refs/gitRebaseVisual/undo/<timestamp>
2. 成功通知里附 [撤销] 按钮
3. 工具栏加 $(discard)，tooltip：撤销上次变基（回到 abc1234）
4. ... 菜单放「最近操作历史」：重排 3 个 commit · 2 分钟前 · abc1234 → def5678
```

## 4️⃣ 变基停靠期间，「未提交的改动」区消失了 —— 与横幅提示自相矛盾

- 截图 1 横幅写着 **「可修改代码或提交新改动后继续。」**
- 但同一屏里**没有任何提交入口**，「未提交的改动」区不见了（对比截图 5）

这是当前最明显的逻辑断裂：**插件在最需要提交能力的时刻收走了提交能力**，用户必须切到 SCM 面板。

建议：edit 停靠期间「未提交的改动」区**必须保留并置于横幅正下方**，且文案切换为停靠语境：

```
┌─────────────────────────────────────────────┐
│ ⏸ 变基停靠 (edit) · 4 / 12                  │
│    31fe2ce  change(cif): split vc shift…     │
│                                             │
│  在此 commit 上的改动：3 个暂存 · 5 个工作区 │
│  [追加到此 commit (amend)]  [新建 commit ▾]  │
│                                             │
│  [Continue]  [Skip]        [Abort]   ⓘ      │
└─────────────────────────────────────────────┘
```

## 5️⃣ 停靠色与锁定色几乎同色 —— 语义冲突

截图 1 中：
- 停靠行 = **金黄色整框高亮**
- 锁定行 = **橙黄色左边框**

两者色相非常接近，在 12 行里同时出现时很难瞬间区分"这行是我停在这儿"还是"这行是别人的锁定提交"。

建议拆开色彩通道：

| 状态 | 建议 token | 形式 |
|---|---|---|
| edit 停靠（安全，信息） | `--vscode-editorInfo-foreground` / `list-activeSelectionBackground` | **蓝色**整行 + 左侧 3px 实心条 |
| 冲突暂停（需处理） | `--vscode-editorError-foreground` | **红色**边框 + ⚠ 图标 |
| 锁定 | `--vscode-editorWarning-foreground` | 橙色左条（保留）+ 🔒 |
| 待应用（见下条） | `opacity: .55` | 无额外颜色 |

# 🟠 P1 — 明显影响体验

## 6️⃣ 变基中"未应用的 commit"没有任何视觉区分（心智模型错误）

截图 1 停在第 4 行，但**第 5–12 行显示的仍是原始 hash**（`f5a8777c6d0d` 等）。

- ❌ 事实上这些 commit **还没被重放**，`git rebase --continue` 之后它们的 hash 会全部变化
- ❌ 当前 UI 让用户误以为"这些 commit 已经就位、hash 就是这个"，进而可能去复制这些 hash 用在别处

建议：

- 🔹 停靠行以下全部 `opacity: .55`
- 🔹 在停靠行下方插入一条分隔：`── 以下 8 个 commit 待重放，hash 将变化 ──`
- 🔹 待应用 commit 的 hash 显示为 `f5a8777*`（加 `*` 或用删除线），tooltip：`将在 Continue 后重新生成`
- 🔹 因为这 8 个里有锁定 commit，额外提示：`Continue 后 8 个已锁定 commit 会被重写（patch-id 锁定仍有效）`

## 7️⃣ 方向锚点信息重复占用 3 行

截图里连续出现：

```
↑ Base / 较早（顶部）· ↓ HEAD / 较新（底部）   ← 图例行
────────────────────────────────────────
↑ Base / 较早                                  ← 顶部锚点行
```

同一件事说了两遍，在 ~330px × 有限高度的侧边栏里代价不小。

建议：**只留首尾锚点行，删掉图例行**：

```
─────── ↑ Base（较早） ───────
  … commits …
─────── ↓ HEAD（较新） ───────
```

- 锚点行做成 sticky 时高度压到 18px、字号 11px、`descriptionForeground`
- 首次打开时用一次性 toast 解释方向，勾选"不再提示"

## 8️⃣ 缺少 upstream 分界线 + 头部上下文（上轮未修）

- 标题仍是 `GIT REBASE: COMMITS`，`COMMITS` 是冗余信息
- 看不出**当前分支 / upstream / 哪些已推送**

建议：

```
GIT REBASE  ·  feature/isp  ↑12 ↓0        ← 视图标题
        …未推送的 commit…
──── ↑ 以上未推送 / origin/feature/isp ────  ← upstream 分界线
        …已推送的 commit（若范围包含）…
```

## 9️⃣ 连续锁定区段应可折叠

截图 5 中 **12 个 commit 有 8 个是锁定的他人提交**——这正是文档描述的典型场景（cherry-pick 一堆依赖）。这 8 行挤占了 2/3 的可视高度，而它们恰恰是**用户最不需要操作**的部分。

建议：

```
▸ 🔒 8 个已锁定的 commit（f5a8777 … 53bee0b）   ← 默认折叠为一行
  ⋮ ● fix(drm): use GEM DMA VMAP driver ops  🔒
```

- 连续 ≥3 个锁定 commit 自动折叠为一行摘要，点击展开
- 折叠行显示作者聚合：`sally_peng ×2 · yucheng_xiang ×1 · lawrence_lv ×5`
- 配置项 `gitRebaseVisual.collapseLockedRuns`（默认 on）

## 🔟 「未提交的改动」区：两个满宽大按钮 + 重复文案

```
未提交的改动: 1 个暂存文件、16 个工作区文件     ← 已经说了数量
[为暂存区生成并提交（1 个文件）]                 ← 又说一遍
[为工作区生成并提交（16 个文件，git add -A）]    ← 又说一遍
```

- ❌ 3 行高度、数量说了三次、两个满宽按钮视觉重量等同"主操作"
- ❌ `为工作区生成并提交` 会执行 `git add -A`（危险度更高），却和安全的暂存区提交**等权重并列**，容易误点

建议收敛为一行主按钮 + 下拉：

```
▸ 未提交的改动   ● 1 staged   ○ 16 unstaged        ← 数字可点，跳 SCM 面板
  [✨ 生成 message 并提交暂存区]  [▾]
                                  └─ 提交全部改动（git add -A）⚠
                                  └─ 仅生成 message（不提交）
```

- 🔹 补一个 **「仅生成 message（不提交）」**：很多人想先拿到 message，自己在 SCM 面板确认后再提交
- 🔹 危险项（`add -A`）收进下拉并加 ⚠

## 1️⃣1️⃣ 「查看」分组里没有任何"查看"动作

截图 4 的菜单：

```
查看
  复制 commit hash          ← 这是"复制"，不是"查看"
编辑与变基
  ...
```

- ❌ 分组名与内容不符
- ❌ 缺 **`打开变更 (diff)`** —— 决定 reword / drop / squash 前想看 diff，是最高频需求，目前完全没有入口
- ❌ 缺 `复制 message`（hover 浮层里有，菜单里没有，入口不一致）

建议：

```
查看
  $(diff)  打开变更…                    ← 新增，vscode.diff 或 git show
  $(copy)  复制 commit hash
  $(copy)  复制 message
```

## 1️⃣2️⃣ 菜单仍缺 squash / fixup，且无图标、无快捷键

- ❌ `squash` / `fixup` 是 `rebase -i` 使用率最高的动作之一，目前依然缺失（只有 reorder / edit / reword / drop）
- ❌ 全部菜单项**无图标**，纯文字列表扫视效率低
- ❌ 无快捷键提示（`Enter` = 编辑 message、`Delete` = drop、`Alt+↑↓` = 重排）

建议「编辑与变基」组补齐：

```
编辑与变基
  $(edit)         编辑 message…                    Enter
  $(sparkle)      AI 生成 message…
  $(add)          追加暂存区（1 个文件）
  $(fold-up)      合并到上一个 (squash)            ← 新增
  $(fold-up)      合并到上一个，丢弃 message (fixup)← 新增
  $(debug-pause)  停靠在此 (edit)
```

- 🔹 `编辑 message 并停靠在此…` 属于组合操作，建议收进 `编辑 message…` 弹窗里的一个勾选项「应用后停靠在此 commit」，菜单少一项

## 1️⃣3️⃣ 变基横幅缺进度与 Skip

- ❌ 无 `4 / 12` 进度 —— 用户不知道还剩多少
- ❌ 无 `Skip`（`git rebase --skip`），冲突场景下这是常用出口
- ❌ 无冲突文件数 / Continue 禁用态（有冲突未 `git add` 时 Continue 应禁用并说明原因）
- ❌ 无状态栏同步：切到编辑器后完全看不出自己处于 rebase 中间态，是"忘记自己在 rebase"的主要成因

建议状态栏：`$(git-branch) rebase 4/12 ⏸ edit`，点击回到面板。

## 1️⃣4️⃣ AI Compose 弹窗：上轮建议基本未落地

截图 3 逐项核对：

| subject / body 拆分 + `50/72` 计数 | ❌ 未做 | 无法约束 subject 长度 |
| body 72 列标尺 | ❌ 未做 | |

| 生成三态 | ❌ 按钮固定写死 `生成 / 重新生成` | 应按状态切换：`✨ 生成` → `⏳ 生成中… [取消]` → `↻ 重新生成` |

## 1️⃣5️⃣ 整行可拖 vs 文本可选，手势冲突

截图 2 hover 时光标是 ✋ grab，说明**整行可拖**。但：

- ❌ 行内 hash `31fe2ce9bf14` **无法双击选中复制**（拖拽劫持了 mousedown）
- ❌ 已经有了 `⋮` grip，整行再可拖就让 grip 失去意义

建议：**拖拽热区限定在 `⋮` grip**（或 grip + 圆点），行内文本恢复可选中；grip 上光标 `grab`，其余区域 `default`。
