## Git Rebase Visual 0.9.0

用于 VS Code 的可视化交互式 Git rebase 扩展：在侧边栏中安全地重排、编辑、锁定和推送 commit，并提供工作区恢复、只读 Diff、AI commit message、stash 与受控 Undo。

> 来源：Git tag `v0.9.0` · GitHub Actions 自动构建 · CI 将执行 `npm run test:release`、VSIX 内容校验与版本记录校验。

### 🎨 界面与可用性（0.9.0）

本轮全部是界面层的改动，**没有改变任何 Git 行为**：状态机、写锁、rebase 流程与推送逻辑原样保留，因此可以放心替换。

- **拖拽开始时会整表跳一下**：`#direction` 提示行在空闲时是 `display:none`，按下 `⋮⋮` 的瞬间它出现，把整个 commit 列表往下推约 24px，光标下的行在按下的那一刻就换了一行。现在这一行常驻，空闲时显示「拖动 ⋮⋮ 重排 · Alt+↑↓ 移动一位」，并且文案随状态变化——过滤中显示「清空搜索后可用」，变基中显示「重排已禁用」，列表还没加载完时显示「正在加载 commit…」而不是谎称没有 commit。
- **拖拽的插入指示线会让行高变化**：插入点原本用 `border-top: 2px` 画，行会被撑高 2px，下方所有行跟着跳；改为 `inset box-shadow` 后位置不变、布局不动。被拖起的行同时获得虚线边框，不再只是变淡。
- **每个作者圆点都像被选中**：圆点描边原本回落到 `--vscode-focusBorder`，常规主题下就是那个蓝色焦点色。现在常规主题无描边，High Contrast 仍由媒体查询给出边框。
- **按钮按下去没有反馈**：现在所有按钮 `:active` 时缩放到 0.97（160ms）。这是本轮唯一新增的动效，其余动效都刻意克制——侧边栏是每天点几十次的地方，加动画只会变慢。
- **右键菜单、悬浮详情、提示横幅的浮层动画**：菜单与悬浮卡从**触发点**放大出现（150ms / 125ms），toast 与横幅只淡入不位移（横幅参与文档流，位移会推列表）。**键盘打开的菜单不播动画**——键盘操作每天重复上百次，动画会被感知为卡顿；悬浮卡首次仍等 400ms 防误触，之后相邻行立即出现。
- **系统开启"减弱动效"时**，这些动画退化为纯淡入，按钮不再缩放。

### 🐛 可读性修复（0.9.0）

以下都经过真实浏览器实测，括号内是改动前 → 改动后：

- 菜单选中项的图标与快捷键提示：灰字压在蓝色选中背景上几乎看不见（**1.67:1 / 1.78:1 → 4.53:1 / 6.31:1**，深色 / 浅色）。
- 危险操作菜单项（删除 commit）在悬停时红字压在蓝底上（**1.35:1 → 4.53:1**）。
- 菜单里的锁与删除 emoji 被 14px 的图标列裁掉 3–4px：图标列改为随字号缩放（`1.4em`），不再裁切。
- 悬浮详情里的统计徽标：徽标背景配了正文描述色（**2.28:1 → 5.83:1**）。
- 未提交改动列表里的 `M` 标记：原本用的是编辑器警告色，而 A/D/R 都用 Git 装饰色，只有 `M` 偏暗（**2.93:1 → 5.88:1**，浅色主题）。现在四者同源。
- 过滤框里有**两个清除入口**：输入框自带 Chromium 的原生 ×，页面又有一个「清除」按钮。现在隐藏原生按钮，保留可 Tab 到的那个。
- **键盘用户看不到主按钮的焦点**：primary 按钮的焦点环与按钮背景同色（深色主题下都是 `#0078D4`），聚焦时不可见。现在焦点环画在按钮内部、用按钮前景色（**1.00:1 → 4.53:1 / 6.31:1**）。

### 🧯 容错与状态（0.9.0）

- **超长错误会把提交列表顶出屏幕**：错误横幅没有高度上界，约 900 字符的报错在 340px 侧边栏里高达 546px，列表只剩 64px（260px 宽时列表**完全不可见**）。现在横幅有高度上界并可内部滚动（45vh），列表恢复 271px；冲突横幅的 Continue / Skip / Abort 滚动到底后完整可见，Tab 也会自动把按钮滚入视野。
- **待重放的 commit 行太淡**：这类行用 0.62 的透明度，元信息（hash、作者、日期与 `*（待重放）` 标记）在深色主题下只有 3.31:1。现在静止态 0.8、悬停态 0.92，元信息达到 4.65:1 / 4.57:1，同时仍明显比正常行淡（约低 30%），一眼能区分。

### ♿ 已知限制（记录在案，未在本版修改）

- 可滚动的**错误横幅没有可聚焦子元素**，纯键盘用户无法在横幅内滚动查看后半段错误。错误文本同时在 `aria-live` 区域播报。
- 待重放行被**选中**时，元信息在深色主题下仍低于 AA（有效 3.37:1）；选中底色本身就只有 4.36:1，单靠透明度无法解决。
- 右键菜单在 **300px 及更窄**的侧边栏会超出面板宽度（322px），右侧快捷键提示被裁。这是既有问题，建议后续版本处理。

### 🧪 验证方式

- 界面改动使用一个新的截图管线验证：把真实 webview（真实标记、真实 CSS/JS、从本机 VS Code 解析的 `--vscode-*` 主题变量）渲染成 PNG，并对每个文本节点计算 WCAG 对比度、裁切与溢出；三条修复批次各自经过独立评审，全部结论要求给出可复现的数字。
- 逻辑与 Git 集成测试保持不变：完整套件 363 项，pass 362、fail 0，1 项因本机缺少 POSIX `sh` 跳过。

### 使用方式

安装 `git-rebase-visual-0.9.0.vsix` 后，从活动栏的 **Git Rebase** 图标打开侧边栏。界面改动即时生效，无需迁移配置；遇到问题可用「Open Logs」查看诊断日志。

### 功能总览

- 拖拽或 Alt+↑/↓ 重排 commit；右键编辑 message、AI 生成 message、squash / fixup、停靠 (edit)、锁定、删除。
- 变基过程中的冲突、edit 停靠与恢复提示，Continue / Skip / Abort 受控执行。
- Changes / Staged Changes 分组：单文件与批量暂存、恢复、删除未跟踪文件。
- Push（含评审 refspec 模板）、Stash / Pop、Undo Last Rewrite、状态重置与诊断日志。

### 文件与系统要求

- VS Code **1.85.0** 及以上；Git **2.31.0** 及以上。
- 支持 Windows、macOS、Linux；界面自动跟随 VS Code 的深色、浅色与 High Contrast 主题。
