## Git Rebase Visual 0.8.5

用于 VS Code 的可视化交互式 Git rebase 扩展：在侧边栏中安全地重排、编辑、锁定和推送 commit，并提供工作区恢复、只读 Diff、AI commit message、stash 与受控 Undo。

> 来源：Git tag `v0.8.5` · GitHub Actions 自动构建 · CI 将执行 `npm run test:release`、VSIX 内容校验与版本记录校验。

### 🐛 修复（0.8.5）

- **改写成功后插件会“卡住”直到超时**：这是本次最重要的修复。一次成功的改写（drop、reorder、reword、追加暂存区、编辑 message）在 Git 已经完成之后，仍会弹出一条带 **Undo** 的完成通知，并**等待用户关闭它**才继续。VS Code 的非模态通知只有在你点击按钮或关闭时才返回，于是你不理它，这个等待就永远不结束——写锁一直没释放，之后任何操作都被拒绝为“上一个操作尚未完成”，约 90 秒后看门狗弹出“已超过 Ns 未完成”。真实日志里 Git 在 `01:56:21` 就改完了，随后 **156 秒没有任何 Git 命令**，158 秒后才强制解除；提交内容一直是正确的，只是界面被自己的通知挡住了。

  - **原因**：这不是设计取舍，是一次回退。0.6 之前完成提示用的是会自动消失的 `toast`（8 秒），0.6 为了加“改完立刻撤销”的按钮，把它换成了被 `await` 的 `showInformationMessage(…, "Undo")`。按钮保留了，但“完成后必须等你关通知”这个副作用没有被注意到。
  - **修复**：完成提示恢复为**纯提示**——没有按钮、不等待、不会被忽略后卡住。**Undo 能力没有丢失**：视图标题栏的 Undo 按钮与 `Git Rebase: Undo Last Rewrite` 命令一直在，现在也仍然可用。
  - **缺锁告警**保留 Undo 按钮（它是“改写后找不到被锁定的 patch”的数据完整性告警，比较少见），但点击后在新的一轮操作锁内执行，不再阻塞当前操作；锁被占用时会给出一条可见提示，而不是只写日志；Undo 失败也不会变成未处理的异常。
  - **改写后必定刷新**：以前“用户点了 Undo 才刷新”，现在只要历史变了就刷新。
  - **告警会点明操作类型**（drop / reorder / append / edit），用户能判断是哪次改写丢了锁定 patch。

- **AI 生成 message 的入口收敛为两个**：现在只有 **右键 commit → AI 生成 message…** 与 **Staged Changes 分组右侧的 ✦ AI 生成 message 并提交暂存区** 两个入口。edit 停靠横幅与「更多提交选项」里的“仅生成 message（不提交）”已删除；`messageOnly` 模式与相关的放行策略一并移除，而不是留下一个无人可达的分支。edit 期间需要 AI 时，先暂存文件再点暂存区的 `✦`。两个入口都是：点 **生成** 只产出草稿，可随意编辑，只有点 **应用** 才真正写入——commit 入口改写该 commit 的 message，暂存区入口用 `git commit -s` 创建带签名的 commit。

- **点了“生成”之后，取消无法退出 AI message 界面**：面板里的关闭按钮用了 `window.confirm`，而 VS Code 的 webview **不支持它**，因此一旦草稿变脏（生成后或编辑后），守卫总是提前返回，只有编辑器标签右上角的 × 能关掉面板。现在 **取消 与 Esc 在任何状态下都能关闭**：空闲、生成中、已生成、已编辑。未应用的草稿本来就有两份持久化，关闭不会丢失，重新打开同一目标会恢复。
  - 还有一个可达状态：面板里有脏草稿时又打开了另一个目标。页面会拒绝覆盖并保留原草稿，此前取消会带着旧会话被宿主拒绝、面板不关。现在页面把这次拒绝报告给宿主，宿主把活动会话移回页面仍在显示的那个；**“旧的保留文档不能关闭较新的目标”的保护原样保留**并有独立用例钉住。

- **推送确认框仍只显示目的地**：确认框曾显示 `评审推送到 origin:refs/for/…？（HEAD:refs/for/…）`，与 0.8.3 起进度标题、成功/失败提示的三要素不一致。现在**确认框也写明推送方式、commit 短标题（不是 hash）与目的地**，原始 refspec 作为“精确发送什么”的细节保留在后面。标题在弹框前从 refspec 的**源端**读取，因此 `HEAD~1:refs/heads/x` 报的是 `HEAD~1` 的标题；源端无法解析时不弹确认框、不推送，并给出可见错误。

- **暂停变基时 commit 右键仍提供会被拒绝的 AI 项**：现在暂停/冲突/edit 停靠时该项置灰并说明“变基进行中；如需 AI message，请先暂存改动并使用暂存区的 ✦”。多选菜单里那个禁用且无动作的 AI 占位项也已移除。

### 🔒 安全与可靠性

- 写锁只覆盖 Git 写入，不再等待用户阅读通知；任何 UI 提示都不会延长锁的持有时间。新增回归用例用一个**永不返回**的通知桩驱动真实改写，断言操作会结束、锁会释放——把它换回旧的 `await` 写法，该用例立刻变红。
- “旧的保留 webview 不能关闭较新的 Compose 目标”的会话校验保持不变，并有独立用例：撤掉校验后该用例变红。
- refspec 进入 `git log` / `git push` 时仍带 `--end-of-options`，注入面没有因为本轮改动而放宽。
- 锁定的 patch、Undo 检查点、`--force-with-lease`、Abort 永不删除文件等既有保证不变。

### 使用方式

- 下载 `git-rebase-visual-0.8.5.vsix`。
- VS Code：扩展面板 → `...` → **Install from VSIX...**。
- 命令行：`code --install-extension git-rebase-visual-0.8.5.vsix`。

### 功能总览

- 交互式 rebase：拖拽重排、Alt+Arrow 重排、edit/reword/squash/fixup/drop、冲突 Continue/Abort；
- 提交保护：patch-id 锁定、Push guard、`--force-with-lease` 与受控 Undo；
- 工作区辅助：Staged/Changes 文件列表、单文件与批量 stage/restore/unstage、VS Code 左右 Diff、auto-stash 与 stash list；
- AI message：右键 commit 与暂存区两个入口、流式生成、deadline、取消、trailer 保留；
- 诊断与质量：OutputChannel、带轮转与脱敏的会话日志、可解释的写锁与看门狗恢复、真实 Git 集成测试、webview DOM 回归、VSIX 内容门禁。
