## Git Rebase Visual 0.6.2

用于 VS Code 的可视化交互式 Git rebase 扩展：在侧边栏与编辑器区中安全地重排、编辑、合并、锁定和推送 commit，支持 AI commit message、stash、暂存区追加与可验证的历史恢复。

> 来源：Git tag `v0.6.2` · GitHub Actions 自动构建 · 已通过 `npm run test:release`、VSIX 内容校验与版本化中文 Release body 校验。

### 🐛 修复（0.6.2）

- **Commit 拖拽无法稳定开始或中途失效**：grip 热区过小、没有显式 drag data、自动 refresh 可能在拖拽中重建列表，导致原生 DnD 被销毁。**修复**：仅 grip 可拖且扩大热区，写入 `dataTransfer`，建立 drag session；拖拽期间延迟 DOM refresh，结束后再安全应用最新 state。宿主根据 source/anchor/placement/revision/完整 canonical order 重新推导并校验移动，防止部分列表、过期状态或伪造 order 改写历史。
- **锁定分组展开/搜索/更多选项会被自动关闭**：状态刷新重建 Webview DOM，丢失 `<details>`、搜索 focus 和 selection。**修复**：保存并恢复 locked run 展开状态、搜索焦点/光标和更多提交选项状态。连续锁定 commit 仅在 `gitRebaseVisual.collapseLockedRuns=true`（默认）且数量 **≥3** 时折叠。
- **无法跨折叠 locked run 重排**：锁定摘要现在支持上/下半区 drop，分别将提交完整插入整组前/后，无需先展开。
- **编辑/AI Panel 原 message 和 trailer 为空**：Webview listener 就绪前可能丢失首个 Compose payload。**修复**：Panel 使用 session/revision/ready/ack delivery queue，首次打开、reload 和重复 ready 都投递最新 payload；dirty draft 不被重复 ready 覆盖，旧 target 不可写入新 target。
- **edit 停靠“仅生成 message”可能提交**：入口现明确使用 draft-only `messageOnly`；宿主只允许暂停 rebase 内 staged/working draft-only Compose，所有 apply/commit 仍走严格白名单。
- **滚动误操作回归防护**：scroll 仅关闭菜单，不发送 host mutation 或持久化 UI state；增加可测试的消息 trace 回归。

### ✨ 交互增强（0.6.2）

- **通知分层**：复制、stash、成功改写等使用面板顶部 inline toast（默认 2.5 秒、替换不堆叠）；warning/error 保持 VS Code 系统通知；Push、AI 和 rebase 使用 SourceControl progress。
- **分支上下文**：面板展示当前 branch、upstream、ahead/behind 与 commit range；无 upstream 和 detached rebase 有明确文案。
- **rebase UI 完整性**：edit 停靠的 Amend/新建 commit/仅生成 message 入口实际渲染并使用 Compose Panel；Amend 保留原 trailer，新 commit 不复制目标 commit 的 trailer。
- **列表/菜单打磨**：搜索计数、字段过滤、Shift 多选、批量安全操作、pending 区块说明、locked run 作者聚合与 hash 范围、菜单/hover 键盘与语义增强。

### 🔒 可靠性与质量

- 继续保持 private Undo ref/journal、patch-id locked continuity audit、冲突 Continue/Skip、stash 恢复和 host-side validation。
- 新增 Compose delivery/session、edit-stop Git 写入、drag reorder、scroll 协议、branch context 等测试；全套测试扩展至 **89 项**。
