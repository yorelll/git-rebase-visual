## Git Rebase Visual 0.5.1

用于 VS Code 的可视化交互式 Git rebase 扩展：在侧边栏中安全地重排、编辑、锁定和推送 commit，支持 AI commit message、stash 与暂存区追加。

> 来源：Git tag `v0.5.1` · GitHub Actions 自动构建 · 已通过 `npm run test:release`、VSIX 内容校验与版本化发布说明校验。

### 🐛 修复（0.5.1）

- **终端 `git switch` / `git stash` 的 index-lock 竞争**：Git Rebase 面板可见时会周期性刷新暂存区和工作区状态；Git 的 `status` 可能顺便刷新 index metadata，短暂创建 `.git/index.lock`，从而与终端切分支、stash 等写 index 操作竞争。**修复**：后台只读状态查询现在显式设置 `GIT_OPTIONAL_LOCKS=0`。状态结果仍然正确，但 Git 不再为可选 index cache refresh 占用 lock。
- **锁行为边界**：该设置严格限定于后台 `git status` 查询；`rebase`、`stash`、`commit`、`push`、`apply`、`switch` 等会写入仓库的操作继续使用 Git 标准 lock，未降低历史改写或工作区写入的安全性。
- **回归覆盖**：新增真实临时仓库测试，预先创建 `.git/index.lock`，验证 `workingStatus()` 与 `isDirty()` 仍正确报告 unstaged 状态和文件数量。

### 🔒 可靠性

- 继续保留 0.5.0 的历史安全保护：locked commit 不可直接 Drop；未解决冲突会禁用 Continue；append Abort 不会重复恢复 stash；reword 暂停/失败时 Compose 保留手写输入。
- GitHub Release workflow 现在要求 tag 所在提交提供 `docs/release-notes/<version>.md`，将其作为最终 Release body 发布；不再使用仅含提交索引的自动 `generate-notes`，也不依赖发布后的人工编辑。

### 使用方式

- 下载 `git-rebase-visual-0.5.1.vsix`。
- VS Code：扩展面板 → `...` → **Install from VSIX...**。
- 命令行：`code --install-extension git-rebase-visual-0.5.1.vsix`。

### 功能总览

- **交互式 rebase**：Base → HEAD 时间轴、拖拽重排、edit/reword/drop、冲突感知的 Continue/Abort；
- **提交保护**：patch-id 锁定、Push guard、`--force-with-lease`；
- **工作区辅助**：auto-stash、精确 stash 恢复提示、stash 列表、将暂存区追加到已有 commit；
- **AI message**：流式生成、超时、取消与 trailer 保留；
- **质量保障**：真实 Git 集成测试、Output 诊断、VSIX 内容和最终发布说明门禁。
