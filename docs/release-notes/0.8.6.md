## Git Rebase Visual 0.8.6

用于 VS Code 的可视化交互式 Git rebase 扩展：在侧边栏中安全地重排、编辑、锁定和推送 commit，并提供工作区恢复、只读 Diff、AI commit message、stash 与受控 Undo。

> 来源：Git tag `v0.8.6` · GitHub Actions 自动构建 · CI 将执行 `npm run test:release`、VSIX 内容校验与版本记录校验。

### 🐛 修复（0.8.6）

- **在 Git 2.31–2.34 上，“追加暂存区”必定失败**：当暂存区里有文件、且工作区存在未跟踪文件（例如 `compile_commands.json`、`.cache/` 下的索引文件）时，点“追加暂存区”会在写入目标 commit 之前中止，并弹出：

  ```text
  追加已暂停：暂存区内容尚未写入目标 commit，因此不能 Continue。
  请选择 Abort 以自动恢复原始改动（原始改动仍保存在 stash 中）。
  ```

  日志里的真实错误是 `恢复未跟踪文件 compile_commands.json 失败：fatal: only one reference expected, 2 given.`

  - **原因**：0.8.3 的“选项注入加固”给所有位置参数加了 `--end-of-options`，其中一处是恢复未跟踪文件用的 `git checkout <stash>^3 -- <path>`。`git checkout` 在 Git 2.31–2.34 上不认这个标记，会把它当成第二个 ref，于是报上面那条错误。扩展声明支持 Git 2.31.0+，因此这是兼容性回归，不是环境问题。
  - **修复**：这一处去掉标记。它本来就不需要——`<stash>` 是 Git 自己产出的完整 40 位 commit id，路径位于 `--` 之后只能是 pathspec，没有任何设置或界面输入进入这条命令。
  - **没有数据损失**：追加在 amend 之前就中止了，原始改动完整保留在 stash 中，Abort 会自动恢复；Continue 在该状态被拒绝是正确行为（索引里没有暂存内容，继续只会重放后续 commit 而不做追加）。

- **同类问题不会再悄悄发生**：把“哪些 Git 子命令接受 `--end-of-options`”从注释变成了代码约束——`checkout` 与 `stash store` 进入拒绝表，`withPositionals` 命中时直接抛错；另有一条静态守卫测试扫描 `src/` 下所有相关调用（包括 `git(...)` 入口与多行写法），一旦有人把标记加回这些命令，**在任何 Git 版本上都会失败**。之前的集成测试抓不到这个问题，因为它跑在 Git 2.53 上，而 2.53 接受该标记。

- **默认启用提示**：扩展激活时显示一次 `Git Rebase Visual <版本> 已启用`（右下角）。同一时刻会做一次只读的 Git 能力检查——`git --version` 是否可用、是否达到最低版本、扩展依赖的参数形式是否被接受。检查失败时改为告警，并说明具体原因（未找到 Git / 版本过低 / 参数形式不被支持），不会报告“已启用”。该检查**每次激活只运行一次**，不会在操作过程中反复执行。

- **诊断信息**：会话日志头部与 OutputChannel 第一行现在记录 `git=<版本>`。此前用户报告“追加失败”时，日志里无法判断 Git 版本，是这次定位慢的直接原因。

### 🔒 安全与可靠性

- 选项注入防护保持不变：refspec、`mainBranch` 等来自设置或界面的字符串在进入 `git log` / `git push` / `git rev-list` 等命令时仍被隔离。本轮只移除了那些**参数可证明为内部值**（完整 40 位提交 id、内部 ref、`--` 之后的路径）的标记，没有放宽任何用户数据路径。
- 追加事务的既有保证不变：amend 之前不写工作区那一半、失败时保持暂停并保留 stash、Abort 永不删除用户文件、只删除插件自己创建的 stash 条目。

### 使用方式

- 下载 `git-rebase-visual-0.8.6.vsix`。
- VS Code：扩展面板 → `...` → **Install from VSIX...**。
- 命令行：`code --install-extension git-rebase-visual-0.8.6.vsix`。

### 功能总览

- 交互式 rebase：拖拽重排、Alt+Arrow 重排、edit/reword/squash/fixup/drop、冲突 Continue/Abort；
- 提交保护：patch-id 锁定、Push guard、`--force-with-lease` 与受控 Undo；
- 工作区辅助：Staged/Changes 文件列表、单文件与批量 stage/restore/unstage、“追加暂存区”、VS Code 左右 Diff、auto-stash 与 stash list；
- AI message：右键 commit 与暂存区两个入口、流式生成、deadline、取消、trailer 保留；
- 诊断与质量：OutputChannel、带轮转与脱敏的会话日志（含 Git 版本）、可解释的写锁与看门狗恢复、真实 Git 集成测试、webview DOM 回归、VSIX 内容门禁。
